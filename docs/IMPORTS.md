# Импорт данных в Life OS

В приложении есть два независимых импортёра — они делают разные вещи, лежат в разных
экранах и ожидают разный формат файла. Оба теперь показывают экран **проверки** перед
тем, как что-либо реально отправить на сервер: файл сначала разбирается на клиенте, вы
правите/одобряете содержимое, и только после подтверждения данные уходят в API.

| | CSV-импорт | Импорт проекта (JSON) |
|---|---|---|
| Где | Настройки → «Выбрать CSV» | Проекты → иконка загрузки (рядом с «+») |
| Формат файла | `.csv` с заголовком | `.json`, один объект |
| Экран проверки | Таблица строк: название, время, проект, одобрение | Дерево задач: чекбокс «принята» вместо удаления |
| Создаёт | только Static-записи плана | проект + дерево задач/подзадач + (опционально) Static-записи |
| Проекты | находит по имени или создаёт | находит по имени или создаёт |
| Часовой пояс | берётся автоматически с телефона | должен быть указан в самом файле (`tz_offset_minutes`), иначе UTC |
| Повторный импорт | всегда добавляет заново (не дедуплицирует) | **дерево задач дедуплицируется** по (название, родитель); Static-записи всегда добавляются заново |
| Серверный эндпоинт | `POST /api/import/csv` | `POST /api/import/project` |

Оба импортёра «best-effort» на уровне отдельных строк: если в файле есть плохая
строка, она пропускается и попадает в список ошибок, а не обрывает весь импорт.
Экран проверки — это ДОПОЛНИТЕЛЬНЫЙ шаг поверх той же логики, а не новый API: он
просто даёт вам исключить/поправить что-то ДО того, как строка попадёт на сервер.

---

## 1. CSV-импорт (Настройки)

Для быстрой загрузки плоского списка запланированных интервалов (Static plan) —
например, если у вас уже есть расписание в таблице.

### Где

Вкладка **Настройки** → кнопка **«Выбрать CSV»** → выбрать файл через системный
файловый пиктер → открывается экран **«Проверка импорта»**.

### Формат файла

Обычный CSV с заголовком в первой строке. Обязательные колонки:

```
project,date,start,end,title
```

- **project** — название проекта (строка).
- **date** — дата в формате `YYYY-MM-DD`, например `2026-08-02`.
- **start** / **end** — время в формате `HH:MM` (24-часовой формат), например `09:30`.
  `end` должен быть строго позже `start` (интервалы через полночь одной строкой не
  поддерживаются — разбейте на две строки).
- **title** — необязательное название записи.

**Известное ограничение**: парсер файла — как на сервере, так и в экране проверки на
телефоне — простой, без поддержки CSV-квотирования (RFC 4180). Если `title` содержит
запятую, разбор сломается. Не используйте запятые внутри полей.

### Экран проверки

После выбора файла открывается таблица — по одной карточке на строку CSV, все поля
редактируемые:

- **Название** — текстовое поле, содержимое колонки `title`.
- **Время** — одно поле в формате `ГГГГ-ММ-ДД ЧЧ:ММ-ЧЧ:ММ` (дата+начало+конец вместе).
  Если ввести неразбираемый текст или конец раньше/равен началу — поле подсвечивается
  ошибкой, а галочка одобрения строки автоматически снимается (можно поправить текст
  и включить одобрение вручную).
- **Проект** — редактируемое поле с выпадающим списком уже существующих проектов.
  Если введённое название не совпадает точно ни с одним существующим — рядом
  появляется пометка **«*новый»** (такой проект будет создан автоматически, как и
  раньше).
- **Одобрение** — кнопка-переключатель (галочка/крестик) справа от карточки. По
  умолчанию все строки одобрены (галочка). Неодобренные строки в импорт не попадают.

Кнопка **«Импортировать (N)»** в шапке показывает, сколько строк сейчас одобрено, и
неактивна, если одобренных строк нет.

### Что происходит при подтверждении

- Только одобренные (и отредактированные, если правили) строки собираются обратно в
  CSV того же формата и отправляются на `/api/import/csv` — с этого момента логика
  та же, что была раньше:
- Каждая строка становится одной Static-записью плана (`PlanEntry`), привязанной к
  проекту по имени.
- Если проект с таким именем не найден — создаётся новый (цвет — следующий по
  очереди из палитры, не настраивается через CSV).
- Строка с ошибкой, обнаруженной уже на сервере (редкость, раз проверка на клиенте её
  обычно ловит раньше), пропускается и попадает в список ошибок.
- Импорт Static-записей **не дедуплицируется**: повторный импорт (или повторное
  одобрение той же строки) создаст запись ещё раз.
- Часовой пояс НЕ указывается в файле — подставляется текущий часовой пояс телефона
  автоматически в момент подтверждения.

### Результат

После импорта под кнопкой «Выбрать CSV» появится строка вида:

```
Импортировано записей: 3, новых проектов: 1, ошибок: 0
```

Если есть ошибки — покажется количество и первая ошибка (`строка N: сообщение`).

## 2. Импорт целого проекта (JSON, вкладка «Проекты»)

Для переноса/восстановления проекта целиком: имя, цвет, дерево чек-листа (задачи и
вложенные на любую глубину подзадачи) и, опционально, уже расписанные Static-записи,
которые могут ссылаться на конкретный пункт чек-листа.

**Терминология**: пункт чек-листа верхнего уровня (без родителя) называется
**«Задача»**. Пункт, вложенный внутрь другого пункта (на любую глубину), называется
**«Подзадача»** — независимо от того, на каком именно уровне вложенности он
находится.

### Где

Вкладка **Проекты** → иконка загрузки файла (кнопка со стрелкой вверх, рядом с
плавающей кнопкой «+» в правом нижнем углу) → выбрать `.json`-файл → открывается
экран **«Проверка импорта»**.

### Формат файла

Один JSON-объект (не массив, не CSV). Задачи теперь могут быть **вложенными** —
каждый элемент `subtasks` сам может содержать свой собственный `subtasks`, рекурсивно,
без ограничения глубины:

```json
{
  "project_name": "Deep work",
  "color": "blue",
  "tz_offset_minutes": 180,
  "subtasks": [
    {
      "title": "Спринт-планирование",
      "done": true,
      "subtasks": [
        { "title": "Написать план", "done": true, "subtasks": [] },
        { "title": "Согласовать с командой", "done": false, "subtasks": [] }
      ]
    },
    { "title": "Ревью кода", "done": false, "subtasks": [] }
  ],
  "static_entries": [
    {
      "date": "2026-08-02",
      "start": "09:00",
      "end": "11:00",
      "name": "Работа над планом",
      "subtask_title": "Написать план"
    }
  ]
}
```

В этом примере «Спринт-планирование» и «Ревью кода» — Задачи (верхний уровень);
«Написать план» и «Согласовать с командой» — Подзадачи, вложенные в «Спринт-планирование».

#### Поля верхнего уровня

- **project_name** (обязательное, непустая строка) — точное имя проекта. Импортёр
  ищет проект по точному совпадению имени; если не находит — создаёт новый.
- **color** (необязательное) — один из: `lavender`, `blue`, `green`, `yellow`,
  `orange`, `red`, `pink`, `gray`. Используется только при СОЗДАНИИ нового проекта.
- **tz_offset_minutes** (необязательное, по умолчанию `0`) — смещение часового пояса
  в минутах от UTC для `date`/`start`/`end` из `static_entries`. **Важно**: в отличие
  от CSV-импорта, часовой пояс телефона здесь НЕ подставляется автоматически — если
  поле не указать, время будет считаться как UTC. Для Москвы (UTC+3) укажите `180`.
- **subtasks** (необязательный массив, по умолчанию пустой) — дерево чек-листа:
  - `title` (обязательное, непустая строка).
  - `done` (необязательное, по умолчанию `false`).
  - `subtasks` (необязательный массив, по умолчанию пустой) — собственные вложенные
    пункты этого пункта, той же формы, рекурсивно.
- **static_entries** (необязательный массив, по умолчанию пустой) — заранее
  расписанные интервалы плана (Static), тот же смысл, что у CSV-импорта:
  - `date` — `YYYY-MM-DD`.
  - `start` / `end` — `HH:MM`, `end` строго позже `start`.
  - `name` (необязательное) — название записи.
  - `subtask_title` (необязательное) — название пункта чек-листа (Задачи или
    Подзадачи), к которому нужно привязать эту запись плана. Резолвится **плоско по
    названию**, без учёта вложенности — известное ограничение: если одинаковое
    название встречается в разных местах дерева, привязка не гарантирована к
    конкретному из них (побеждает последний найденный при обходе).

### Экран проверки

После выбора файла открывается дерево (визуально похоже на экран открытого проекта):

- Заголовок — название проекта из файла и пометка **«новый проект»** /
  **«существующий проект»** (сверка с уже загруженным списком проектов).
- Ниже — дерево задач с отступами по уровню вложенности, шевроном
  свернуть/развернуть у пунктов с вложенными подзадачами, и вычеркнутым текстом для
  пунктов с `"done": true`.
- Справа от каждого пункта — **ЛИБО** чекбокс «принята» (по умолчанию включён —
  пункт будет импортирован), **ЛИБО**, если этот пункт по названию и позиции в
  дереве совпадает с уже существующим пунктом того же проекта, надпись **«уже есть»**
  без чекбокса (взаимодействовать с ним нельзя — он и так не будет задвоен).
- Снятие галочки у пункта исключает из импорта **весь его поддерево** целиком (все
  вложенные подзадачи под ним тоже не импортируются), даже если у них отдельно стоит
  галочка — она в этом случае просто не имеет эффекта.
- Пометка «уже есть» в этом экране — **сверка только на телефоне**, для удобства
  просмотра. Настоящую (не)дупликацию решает сервер при подтверждении (см. ниже) —
  если что-то на телефоне и на сервере разошлось (например, кто-то другой добавил
  такую же задачу с другого устройства между открытием этого экрана и подтверждением),
  сервер всё равно не создаст дубликат.

Кнопка **«Импортировать»** в шапке отправляет только принятые (не снятые с галочки)
пункты дерева, вместе с `static_entries` как есть (они на этом экране не
редактируются).

### Что происходит при подтверждении

1. Проект ищется по `project_name`; если не найден — создаётся с указанным (или
   автоматическим) цветом.
2. Дерево `subtasks` обходится рекурсивно. Для каждого пункта: если СУЩЕСТВУЕТ пункт
   с ТАКИМ ЖЕ названием под тем же родителем (тем же уровнем дерева) — он
   **переиспользуется** (новый не создаётся, состояние `done` существующего пункта
   НЕ меняется), а не создаётся дубликат. Если не существует — создаётся новый со
   значением `done` из файла.
3. **Дедупликация работает и ВНУТРИ одного файла**: если в самом импортируемом дереве
   два соседних пункта с одинаковым названием под одним родителем — второй
   переиспользует только что созданный первым, а не станет отдельным дублем.
4. Каждый элемент `static_entries` становится Static-записью плана (эта часть
   импорта, в отличие от чек-листа, **не дедуплицируется** — повторный импорт того
   же файла снова создаст те же записи плана); если указан `subtask_title`, он
   резолвится плоским поиском по названию (см. известное ограничение выше).
5. Проблемная строка `static_entries` (плохая дата/время, `end <= start`,
   ненайденный `subtask_title`) пропускается/создаётся без привязки и попадает в
   список ошибок — остальные строки всё равно обрабатываются.
6. Ошибка запроса целиком (невалидный JSON, пустой `project_name`) отклоняет весь
   запрос с кодом 422 — тут «best-effort» не применяется.

### Результат

После импорта под списком проектов появится строка вида:

```
Проект создан, задач: 3, уже было: 0, записей плана: 1, ошибок: 0
```

или, при повторном импорте того же дерева в уже существующий проект:

```
Проект обновлён, задач: 0, уже было: 3, записей плана: 1, ошибок: 0
```

## Частые ошибки

- **JSON-импорт «уехал» на несколько часов** — не указали (или указали неверно)
  `tz_offset_minutes` в файле. CSV-импорт этой проблемы не имеет (берёт часовой
  пояс с телефона сам).
- **Static-записи задвоились при повторном импорте** — `static_entries` (в обоих
  импортёрах) и CSV-строки не дедуплицируются, они всегда добавляются заново.
  Дедуплицируется только дерево задач/подзадач JSON-импорта. Прежде чем повторно
  импортировать один и тот же файл, проверьте, действительно ли нужно повторять
  именно Static-записи (при повторном импорте задач/подзадач ничего не задвоится).
- **`subtask_title not found`** — название в `static_entries[].subtask_title`
  должно ТОЧНО совпадать (включая регистр и пробелы) с `title` где-то в дереве
  `subtasks`, либо с названием уже существующего пункта чек-листа этого проекта.
- **Задача осталась невыделенной в экране проверки, хотя должна быть новой** — если
  родительская задача помечена «уже есть», а сама она — нет, значит по названию она
  не совпала ни с одним существующим пунктом под этим родителем; это ожидаемо, если
  название хоть немного отличается (сверка точная, без учёта регистра НЕ делается).
- **Файл не открылся / «не удалось разобрать файл»** — проверьте, что выбран файл
  нужного типа (`.csv` для Настроек, `.json` для Проектов) и что в нём валидный
  синтаксис (для JSON — например, пропущенная запятая или незакрытая скобка ломает
  разбор файла целиком, это происходит ещё до появления экрана проверки).

## Технические детали (для тех, кто пишет файл руками или скриптом)

- Экраны проверки — это чисто клиентская логика (парсинг, редактирование, фильтрация
  по галочкам). Сама отправка на сервер по-прежнему идёт на те же два эндпоинта, что
  и раньше — если вы пишете файл вручную и шлёте его напрямую через curl/Postman, экран
  проверки вы просто не увидите, но данные обработаются так же.
- CSV: `POST /api/import/csv`, тело `{"csv": "<весь текст файла>", "tz_offset_minutes": <int>}`.
- JSON-проект: `POST /api/import/project`, тело — сам JSON-файл как есть (см. схему
  выше, включая рекурсивное поле `subtasks`).
- Оба эндпоинта не требуют авторизации локально; если сервер развёрнут за
  Cloudflare Access (как в проде), Android-клиент добавляет заголовки
  `CF-Access-Client-Id` / `CF-Access-Client-Secret` из Настроек — при ручных
  запросах через curl их нужно будет передать самостоятельно.
