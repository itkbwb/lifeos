# Импорт данных в Life OS

В приложении есть два независимых импортёра — они делают разные вещи, лежат в разных
экранах и ожидают разный формат файла. Не путайте их.

| | CSV-импорт | Импорт проекта (JSON) |
|---|---|---|
| Где | Настройки → «Выбрать CSV» | Проекты → иконка загрузки (рядом с «+») |
| Формат файла | `.csv` с заголовком | `.json`, один объект |
| Создаёт | только Static-записи плана | проект + подзадачи + (опционально) Static-записи |
| Проекты | находит по имени или создаёт | находит по имени или создаёт |
| Часовой пояс | берётся автоматически с телефона | должен быть указан в самом файле (`tz_offset_minutes`), иначе UTC |
| Повторный импорт | всегда добавляет заново (не дедуплицирует) | всегда добавляет заново (не дедуплицирует) |
| Серверный эндпоинт | `POST /api/import/csv` | `POST /api/import/project` |

Оба импортёра «best-effort»: если в файле есть плохая строка, она пропускается и
попадает в список ошибок, а не обрывает весь импорт.

---

## 1. CSV-импорт (Настройки)

Для быстрой загрузки плоского списка запланированных интервалов (Static plan) —
например, если у вас уже есть расписание в таблице.

### Где

Вкладка **Настройки** → кнопка **«Выбрать CSV»** → выбрать файл через системный
файловый пиктер.

### Формат

Обычный CSV с заголовком в первой строке. Обязательные колонки:

```
project,date,start,end,title
```

- **project** — название проекта (строка). Если проекта с таким именем ещё нет, он
  будет создан автоматически (цвет назначается по кругу из палитры — вы его не
  выбираете).
- **date** — дата в формате `YYYY-MM-DD`, например `2026-08-02`.
- **start** / **end** — время в формате `HH:MM` (24-часовой формат), например `09:30`.
  `end` должен быть строго позже `start` (интервалы через полночь одной строкой не
  поддерживаются — разбейте на две строки).
- **title** — необязательное название записи. Если пусто — запись будет без имени
  (просто время + проект).

Часовой пояс НЕ указывается в файле — Android-приложение подставляет текущий
часовой пояс телефона автоматически в момент импорта.

### Пример файла

```csv
project,date,start,end,title
Deep work,2026-08-02,09:00,11:00,Спринт-планирование
Deep work,2026-08-02,14:00,16:30,
Reading,2026-08-03,20:00,21:00,Книга
```

Эта строка создаст 3 Static-записи плана; если проектов «Deep work» и «Reading»
ещё нет — создаст и их.

### Что происходит при импорте

- Каждая строка становится одной Static-записью плана (`PlanEntry`), привязанной к
  проекту по имени.
- Если проект с таким именем не найден — создаётся новый (цвет — следующий по
  очереди из палитры, не настраивается через CSV).
- Строка с ошибкой (некорректная дата/время, `end <= start`, пустой `project`)
  пропускается и попадает в список ошибок — остальные строки всё равно
  импортируются.
- Импорт **не дедуплицирует**: повторный импорт того же файла создаст те же записи
  ещё раз (задвоит их).
- Подзадачи (чеклист) через CSV не создаются и не связываются — для этого нужен
  JSON-импорт проекта (см. ниже).

### Результат

После импорта под кнопкой появится строка вида:

```
Импортировано: 3, создано проектов: 1 (Reading), ошибок: 0
```

Если есть ошибки — покажется количество и первая ошибка (`строка N: сообщение`).

## 2. Импорт целого проекта (JSON, вкладка «Проекты»)

Для переноса/восстановления проекта целиком: имя, цвет, чеклист (подзадачи) и,
опционально, уже расписанные Static-записи, которые могут ссылаться на конкретный
пункт чеклиста.

### Где

Вкладка **Проекты** → иконка загрузки файла (кнопка со стрелкой вверх, рядом с
плавающей кнопкой «+» в правом нижнем углу) → выбрать `.json`-файл.

### Формат

Один JSON-объект (не массив, не CSV):

```json
{
  "project_name": "Deep work",
  "color": "blue",
  "tz_offset_minutes": 180,
  "subtasks": [
    { "title": "Написать план", "done": true },
    { "title": "Ревью кода", "done": false }
  ],
  "static_entries": [
    {
      "date": "2026-08-02",
      "start": "09:00",
      "end": "11:00",
      "name": "Спринт-планирование",
      "subtask_title": "Написать план"
    },
    {
      "date": "2026-08-02",
      "start": "14:00",
      "end": "15:00"
    }
  ]
}
```

#### Поля верхнего уровня

- **project_name** (обязательное, непустая строка) — точное имя проекта. Импортёр
  ищет проект по точному совпадению имени; если не находит — создаёт новый.
- **color** (необязательное) — один из: `lavender`, `blue`, `green`, `yellow`,
  `orange`, `red`, `pink`, `gray`. Используется только при СОЗДАНИИ нового проекта
  (если проект с таким именем уже существует — его цвет не меняется). Если не
  указано — выбирается автоматически из палитры.
- **tz_offset_minutes** (необязательное, по умолчанию `0`) — смещение часового
  пояса в минутах от UTC, в котором нужно понимать `date`/`start`/`end` из
  `static_entries`. **Важно**: в отличие от CSV-импорта, здесь часовой пояс телефона
  НЕ подставляется автоматически — если поле не указать, время будет считаться как
  UTC, и записи «уедут» на несколько часов от ожидаемого времени. Для Москвы
  (UTC+3) укажите `180`.
- **subtasks** (необязательный массив, по умолчанию пустой) — пункты чеклиста
  проекта:
  - `title` (обязательное, непустая строка) — текст пункта.
  - `done` (необязательное, по умолчанию `false`) — отмечен ли пункт выполненным.
- **static_entries** (необязательный массив, по умолчанию пустой) — заранее
  расписанные интервалы плана (Static), тот же смысл, что у CSV-импорта:
  - `date` — `YYYY-MM-DD`.
  - `start` / `end` — `HH:MM`, `end` строго позже `start`.
  - `name` (необязательное) — название записи.
  - `subtask_title` (необязательное) — точное название пункта из `subtasks` (или
    уже существующего у проекта пункта из более раннего импорта), к которому нужно
    привязать эту запись плана. Если указанного заголовка не нашлось — запись всё
    равно создаётся, но БЕЗ привязки к подзадаче, и это попадает в список ошибок.

### Что происходит при импорте

1. Проект ищется по `project_name`; если не найден — создаётся с указанным (или
   автоматическим) цветом.
2. Каждый элемент `subtasks` добавляется как НОВЫЙ пункт чеклиста в конец списка
   (позиция продолжается от уже существующих пунктов проекта) — **не
   дедуплицируется по названию**: повторный импорт того же файла создаст дубликаты
   пунктов чеклиста.
3. Каждый элемент `static_entries` становится Static-записью плана; если указан
   `subtask_title`, он ищется среди ВСЕХ подзадач проекта (только что созданных
   этим же импортом И уже существовавших ранее) и запись привязывается к найденной
   подзадаче.
4. Проблемная строка `static_entries` (плохая дата/время, `end <= start`,
   ненайденный `subtask_title`) пропускается/создаётся без привязки и попадает в
   список ошибок — остальные строки всё равно обрабатываются.
5. Ошибка транзакции целиком (например, невалидный JSON или пустой
   `project_name`) отклоняет весь запрос с кодом 422 — тут «best-effort» не
   применяется, это про НЕВАЛИДНЫЙ файл целиком, а не про отдельные строки.

### Результат

После импорта под списком проектов появится строка вида:

```
Проект создан, подзадач: 2, записей плана: 2, ошибок: 0
```

или, если проект уже существовал:

```
Проект обновлён, подзадач: 2, записей плана: 1, ошибок: 1 (строка 2: subtask_title not found: 'Опечатка')
```

## Частые ошибки

- **JSON-импорт «уехал» на несколько часов** — не указали (или указали неверно)
  `tz_offset_minutes` в файле. CSV-импорт этой проблемы не имеет (берёт часовой
  пояс с телефона сам).
- **Повторный импорт задвоил подзадачи/записи** — оба импортёра не проверяют
  «уже было это или нет», они всегда добавляют заново. Прежде чем повторно
  импортировать один и тот же файл, убедитесь, что предыдущий импорт действительно
  нужно повторить (например, удалите старые записи вручную).
- **`subtask_title not found`** — название в `static_entries[].subtask_title`
  должно ТОЧНО совпадать (включая регистр и пробелы) с `title` в `subtasks`, либо с
  названием уже существующего пункта чеклиста этого проекта.
- **Файл не открылся / «не удалось импортировать»** — проверьте, что выбран файл
  нужного типа (`.csv` для Настроек, `.json` для Проектов) и что в нём валидный
  синтаксис (для JSON — например, пропущенная запятая ломает весь файл, это будет
  ошибкой 422, а не построчной).

## Технические детали (для тех, кто пишет файл руками или скриптом)

- CSV: `POST /api/import/csv`, тело `{"csv": "<весь текст файла>", "tz_offset_minutes": <int>}`.
- JSON-проект: `POST /api/import/project`, тело — сам JSON-файл как есть (см. схему
  выше). Технически это то же самое, что отправить в Postman/curl.
- Оба эндпоинта не требуют авторизации локально; если сервер развёрнут за
  Cloudflare Access (как в проде), Android-клиент добавляет заголовки
  `CF-Access-Client-Id` / `CF-Access-Client-Secret` из Настроек — при ручных
  запросах через curl их нужно будет передать самостоятельно.
