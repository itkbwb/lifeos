# Life OS — Android client

Kotlin + Jetpack Compose клиент: тёмная лавандовая тема, рабочий доступ к
серверу (адрес + Cloudflare Access), механизм автообновления и минимальный
экран «Проекты» (глава 1 новой архитектуры). Остальные экраны с данными
(расписание, статистика и т.д.) пока не реализованы и будут спроектированы
отдельными главами.

## Локальная разработка

Нужен Android Studio (Koala/2024.1+) с установленным Android SDK. При первом
открытии проекта в Android Studio:

1. `File → Open` → выбрать папку `android/`.
2. Дать Android Studio синхронизировать Gradle (обёртки `gradlew` в
   репозитории намеренно нет — Android Studio восстановит её через
   `Tools → Gradle → Generate wrapper`, если понадобится собирать без IDE).
3. Запустить конфигурацию `app` на эмуляторе или физическом телефоне.

## Настройка адреса сервера

По умолчанию приложение обращается на `https://life-os.vip`. Меняется в
приложении: экран «Настройки» → поле адреса сервера → «Сохранить». Значение
хранится в DataStore на телефоне, Cloudflare Access Service Token — в
зашифрованном хранилище (`EncryptedSharedPreferences`). Кнопка «Проверить
подключение» дёргает `GET /health`, чтобы подтвердить, что сервер отвечает —
это сейчас единственный эндпоинт, который вообще есть на сервере.

Так как сервер может работать и по обычному HTTP в локальной сети,
`AndroidManifest.xml` включает `usesCleartextTraffic="true"`.

## Что есть сейчас

- Тёмная лавандовая тема (`ui/theme/Color.kt`, `ui/theme/Theme.kt`) плюс
  фиксированная палитра цветов проекта (lavender/blue/green/yellow/orange/
  red/pink/gray, `ui/theme/ProjectColors.kt`).
- Стартовый экран — «Проекты» (`ui/ProjectsScreen.kt`): список проектов с
  сервера, создание («+»), редактирование имени/цвета и удаление (с
  подтверждением) через диалоги в `ui/ProjectDialogs.kt`. При недоступности
  сервера показывается сообщение с кнопками «Повторить»/«Настройки» вместо
  падения — локальной копии проектов нет, сервер остаётся единственным
  источником истины.
- Экран «Настройки» (открывается кнопкой сверху на экране Проектов): адрес
  сервера, Cloudflare Access Service Token, ручная проверка подключения,
  ручная проверка/установка обновления, версия приложения.
- `data/ApiFactory.kt` — OkHttp+Gson клиент: `GET /health` и CRUD
  `/api/projects` (`listProjects`/`createProject`/`updateProject`/`deleteProject`).
- Автопроверка обновлений при каждом запуске через GitHub Releases
  (`app/src/main/java/com/lifeos/app/update/UpdateChecker.kt`) — сравнивает
  `versionName` с последним релизом `itkbwb/lifeos`, при наличии новой версии
  скачивает APK и предлагает установку.

## Чего нет (сознательно)

Расписание, календарь, статистика, задачи внутри проекта, архив/soft-delete —
будут спроектированы отдельными главами. Модель проекта сейчас содержит
только `id`, `name`, `color`, `created_at` — без описаний, дедлайнов,
приоритетов и связей с другими сущностями.
