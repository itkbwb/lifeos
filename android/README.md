# Life OS — Android client

Kotlin + Jetpack Compose клиент: тёмная лавандовая тема, рабочий доступ к
серверу (адрес + Cloudflare Access), механизм автообновления, экран
«Проекты» (глава 1), календарь Year/Month/Week/Day (глава 2) и Timeline —
события start/end/instant, отображаемые прямо в дневной сетке календаря
(глава 3). Остальное (планирование, аналитика, отчёты) пока не реализовано
и будет спроектировано отдельными главами.

## Локальная разработка

Нужен Android Studio (Koala/2024.1+) с установленным Android SDK. При первом
открытии проекта в Android Studio:

1. `File → Open` → выбрать папку `android/`.
2. Дать Android Studio синхронизировать Gradle (обёртки `gradlew` в
   репозитории намеренно нет — Android Studio восстановит её через
   `Tools → Gradle → Generate wrapper`, если понадобится собирать без IDE).
3. Запустить конфигурацию `app` на эмуляторе или физическом телефоне.

## Настройка адреса сервера

По умолчанию приложение обращается на `https://life-os.vip`. Меняется в
приложении: экран «Настройки» → поле адреса сервера → «Сохранить». Значение
хранится в DataStore на телефоне, Cloudflare Access Service Token — в
зашифрованном хранилище (`EncryptedSharedPreferences`). Кнопка «Проверить
подключение» дёргает `GET /health`, чтобы подтвердить, что сервер отвечает —
это сейчас единственный эндпоинт, который вообще есть на сервере.

Так как сервер может работать и по обычному HTTP в локальной сети,
`AndroidManifest.xml` включает `usesCleartextTraffic="true"`.

## Что есть сейчас

- Тёмная лавандовая тема (`ui/theme/Color.kt`, `ui/theme/Theme.kt`) плюс
  фиксированная палитра цветов проекта (lavender/blue/green/yellow/orange/
  red/pink/gray, `ui/theme/ProjectColors.kt`).
- Нижняя навигация из трёх разделов: Календарь (стартовый), Проекты,
  Настройки.
- «Проекты» (`ui/ProjectsScreen.kt`): список с сервера, создание («+»),
  редактирование/удаление через `ui/ProjectDialogs.kt`. У каждого проекта —
  кнопка старт/стоп сессии (▶/■) и кнопка «💥» для мгновенной отметки
  (`instant`, без названия). Старт сессии открывает диалог с названием
  события (по умолчанию предзаполнено именем проекта, но может быть любым —
  событие не обязано называться так же, как проект) и создаёт `start`
  в Timeline с этим названием (`label`). Одновременно может идти только один
  проект — попытка начать другой при уже активном открывает диалог с тремя
  вариантами (завершить текущий / отменить / завершить и начать новый).
  При недоступности сервера — сообщение с «Повторить»/«Настройки» вместо
  падения, локальной копии данных нет.
- «Календарь» (`ui/calendar/`): Year/Month/Week/Day с переходами как в
  Google Calendar (глава 2) плюс отображение Timeline прямо в дневной сетке
  (глава 3, `DayTimelineView.kt` + `TimelineLayout.kt`): сетка с делениями
  по 10 минут, завершённые интервалы — сплошной блок цвета проекта с
  названием события внутри, незавершённая сессия — 20-минутный блок с
  градиентом от полной непрозрачности до прозрачного по всей высоте,
  `instant`-события — тонкая линия с перекрашиваемой в цвет проекта иконкой
  (`Icons.Default.Star`, без фонового кружка), положение иконки на линии —
  псевдослучайное, но детерминированное по `id` события (одинаковое при
  каждом запуске, чтобы соседние отметки не перекрывались). Интервалы
  кликабельны, `instant`-отметки — нет (просмотр/правка мгновенных событий —
  отдельная задача, через будущий журнал Timeline).
- Экран «Настройки»: адрес сервера, Cloudflare Access Service Token, ручная
  проверка подключения, ручная проверка/установка обновления, версия
  приложения.
- `data/ApiFactory.kt` — OkHttp+Gson клиент: `GET /health`, CRUD
  `/api/projects`, и Timeline (`listEvents`/`createEvent`/`getActiveProject`/
  `correctEvent`) поверх `/api/events`.
- Автопроверка обновлений при каждом запуске через GitHub Releases
  (`app/src/main/java/com/lifeos/app/update/UpdateChecker.kt`) — сравнивает
  `versionName` с последним релизом `itkbwb/lifeos`, при наличии новой версии
  скачивает APK и предлагает установку.

## Чего нет (сознательно)

Планирование, аналитика, отчёты, редактирование/просмотр `instant`-событий
через отдельный журнал, ввод текстовой метки при отметке — будут
спроектированы отдельными главами. Интервалы, пересекающие полночь,
рисуются как два независимых блока (без общего состояния между соседними
днями).
